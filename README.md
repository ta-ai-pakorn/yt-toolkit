# YT Toolkit

เครื่องมือจัดการสื่อจากยูทูปที่รันบนเครื่องของคุณ เปิดผ่านเบราว์เซอร์ที่ `http://127.0.0.1:8787`
เอกสาร: [BRD.md](BRD.md) · [PRD.md](PRD.md)

## ติดตั้งบน Windows (ทำครั้งเดียว)
1. ลง Git: เปิด PowerShell แล้ววาง `winget install Git.Git`
2. รับคำเชิญเข้า repo นี้ที่ GitHub
3. วางคำสั่งนี้ใน PowerShell (ครั้งแรกจะเด้งให้ล็อกอิน GitHub ผ่านเบราว์เซอร์)
   ```powershell
   git clone https://github.com/ta-ai-pakorn/yt-toolkit.git "$env:USERPROFILE\YT-Toolkit"
   ```
4. เปิดโฟลเดอร์ `YT-Toolkit` แล้วดับเบิลคลิก `start.bat`

## เปิดและปิดโปรแกรม
- เปิด: ดับเบิลคลิก `start.bat` (อัปเดตเวอร์ชันใหม่ให้เองทุกครั้ง)
- ปิด: ดับเบิลคลิก `stop.bat` หรือคลิกขวาไอคอนสีอำพันที่มุมขวาล่าง → "ปิดโปรแกรม" หรือกดปุ่ม "ปิดโปรแกรม" ในหน้าตั้งค่า
  (บน Windows 11 ถ้าไม่เห็นไอคอน ให้กดลูกศร `^` ที่มุมขวาล่างของแถบงาน ไอคอนอาจซ่อนอยู่ในนั้น)

## สำหรับผู้พัฒนา
```bash
uv sync                                   # ลง dependency รวมชุดเทส
uv run pytest                             # เทส Python
uv run python -m yttoolkit serve --dev    # backend (port 8787)
cd web && npm install && npm run dev      # หน้าเว็บ (port 5173) ต่อกับ backend ข้างบน
cd web && npm test && npm run e2e         # เทสหน้าเว็บ
cd web && npm run build                   # build แล้ว commit web/dist ด้วยทุกครั้ง
```

- เปิด backend (`serve --dev`) ให้เรียบร้อยก่อนสั่ง `npm run dev` ทุกครั้ง เพราะ vite ต่อเข้า backend ตามพอร์ตที่เห็นตอนเริ่มรัน
- ถ้าพอร์ตของ backend เปลี่ยน (เช่น 8787 ถูกใช้อยู่) ให้ปิดแล้วเปิด vite ใหม่
- log ของโปรแกรมที่เปิดด้วย `start.bat` อยู่ที่ `run/logs/app.log` รวมถึงกรณีโหลดไลบรารีไม่ขึ้น ถ้าเปิดไม่ขึ้นให้เปิดไฟล์นี้ดูก่อน ส่วน `serve` แสดง log ในหน้าต่าง terminal แทน

### ทำงานกับหน้าเว็บโดยไม่ต้องต่อเน็ต (`YT_TOOLKIT_FAKE=1`)
ปกติทุกครั้งที่วางลิงก์ แอพจะไปถามยูทูปจริง ซึ่งช้า และผลเปลี่ยนไปเรื่อย ๆ ถ้าจะแก้หน้าเว็บหรือรันเทสหน้าเว็บ ให้เปิดโหมดข้อมูลปลอมแทน แอพจะอ่านข้อมูลคลิปที่เก็บไว้ในโฟลเดอร์ `tests/fixtures/` (เป็นข้อมูลจริงที่ตัดมาเก็บไว้) โดยไม่ต่อยูทูปเลย เทียบได้กับการซ้อมบนสนามจำลอง หน้าตาและการทำงานเหมือนของจริง แต่ผลออกมาเหมือนเดิมทุกครั้ง

```bash
YT_TOOLKIT_FAKE=1 uv run python -m yttoolkit serve --dev   # backend แบบข้อมูลปลอม
cd web && npm run e2e                                      # เทส E2E เปิดโหมดนี้ให้เองอยู่แล้ว (ตั้งใน web/playwright.config.ts)
```

รัน E2E หลายชุดพร้อมกันได้ด้วย `E2E_PORT` เช่น `E2E_PORT=8811 npm run e2e` แต่ละชุดใช้พอร์ตและโฟลเดอร์ข้อมูลชั่วคราวของตัวเอง ไม่ชนกับชุดปกติที่พอร์ต 8799 ครับ

หมายเหตุ: หน้าตรวจสุขภาพยังเช็ก PyPI และยูทูปจริงอยู่ (เจอเน็ตหลุดก็แค่ขึ้นเตือน ไม่พัง) และถ้าอยากวัดเวลาจริงกับยูทูป ให้รัน `uv run pytest -m network -q -s` ซึ่งไม่ได้รันใน CI ครับ

โหมดนี้ใช้ได้กับ `serve` เท่านั้น ส่วน `start.bat` ต่อยูทูปจริงเสมอแม้จะตั้ง `YT_TOOLKIT_FAKE=1` ค้างไว้ และตอนเปิดโหมดนี้ หน้าตรวจสุขภาพจะมีแถบ "โหมดข้อมูลปลอม" บอกไว้ให้เห็นชัด ๆ ครับ

### ภาพเฟรมของคลิปยาวจะไม่คมเท่าคลิปสั้น
คลิปยาว (เช่น 1 ชั่วโมง) ยูทูปให้ภาพเฟรมแบบเร็วที่เล็กลงเหลือราว 160×90 (คลิป 10 นาทีได้ 320×180) ภาพที่ขึ้นตอนเอาเมาส์ชี้และ contact sheet ของคลิปยาวจึงดูนุ่มกว่า เป็นเรื่องปกติ ไม่ใช่บั๊กครับ โหมดภาพคมใน M5 จะแก้เรื่องนี้
