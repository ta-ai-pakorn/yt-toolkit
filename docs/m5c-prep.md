## 1. รอบ C ต้องส่งมอบอะไร (ตาม PRD)

- **แท็บ "ขั้นสูง" ในหน้าตั้งค่า (W6, `/settings/advanced`)**: Switch "ใช้คุกกี้ยูทูป" (ปิดเป็นค่าเริ่มต้น) · เลือกแหล่ง "ไฟล์ cookies.txt" หรือ "Firefox" · ปุ่ม "นำเข้า cookies.txt" · ข้อความเรื่อง Chrome 127 · บรรทัดสถานะ "นำเข้าเมื่อ <วันที่>" · ปุ่มรอง "ลบคุกกี้" (FR-CK-1, 2, 6 · AC-CK-08)
- **กล่องเตือนตอนเปิดครั้งแรก (W7)**: Alert Dialog เรื่องบัญชีอาจถูกจำกัด/ล็อก กระทบ Gmail และ Drive ให้ใช้บัญชีสำรอง อย่าส่งไฟล์ให้ใคร · ปุ่ม "ยกเลิก" / "เปิดใช้คุกกี้" · กดยกเลิกแล้วต้องไม่มีไฟล์ใด ๆ ใน `data/` (FR-CK-3 · AC-CK-02)
- **API `/cookies*`**: `POST /cookies/import {text}` (ไม่เกิน 1 MB, ต้องยอมรับคำเตือนก่อน ไม่งั้น 409, ไฟล์ใช้ไม่ได้ 422 `E_COOKIES_INVALID`) และ `DELETE /cookies` · ค่าตั้ง `cookies` = `{enabled, source, warningAccepted, importedAt?}` แก้ผ่าน `PATCH /settings` ไม่ได้ (AC-CK-03, 04, 05)
- **เก็บที่เดียว กรองโดเมน**: เก็บเป็น `data/cookies.txt` เหลือแค่ `youtube.com` และ `google.com` ห้ามมีสำเนาใน `work/`, `run/`, โฟลเดอร์ผลลัพธ์ หรือไฟล์สำรองค่าตั้ง · โหมด Firefox ไม่เก็บอะไรเลย อ่านสดทุกครั้ง (FR-CK-4)
- **ใช้เฉพาะเมื่อจำเป็น**: ทุกคำขอลองแบบไม่ใช้คุกกี้ก่อน ใช้คุกกี้เฉพาะ (1) ลองซ้ำ 1 ครั้งหลังได้ `E_AGE_RESTRICTED` / `E_VIDEO_PRIVATE` (ทั้งตอนดึงข้อมูลและตอนโหลด) หรือ (2) ผู้ใช้ติ๊ก "ใช้คุกกี้กับคลิปนี้" ในตัวเลือกขั้นสูงของ W2 (ส่ง `useCookies` ใน `POST /jobs`) · **ไม่ใช้กับ `E_BOT_CHECK`** · ครั้งที่ใช้คุกกี้ใช้แทนเซสชันผู้ชม ไม่ใช้สองไฟล์พร้อมกัน (FR-CK-7 · AC-CK-06)
- **ไม่หลุดออกทาง log/รายงาน**: ค่าคุกกี้ห้ามอยู่ใน `app.log`, รายงานแจ้งปัญหา, `detail` ของ error และคำตอบ API ใด ๆ · ห้ามใช้ `verbose` / `print_traffic` ตอนใช้คุกกี้ · มีเทส canary (FR-CK-5 · AC-SET-06)
- **แถว "คุกกี้" ใน `/health`**: ปิดอยู่ / เปิด ใช้ไฟล์ (วันที่นำเข้า) / เปิด ใช้ Firefox / อ่านไม่ได้ (พร้อมวิธีแก้) (FR-CK-8 · AC-CK-07)
- **ข้อความ error รุ่น M5**: `E_AGE_RESTRICTED` และ `E_VIDEO_PRIVATE` เปลี่ยนเป็นข้อความที่บอกว่าเปิดคุกกี้ได้ที่ ตั้งค่า > ขั้นสูง · ข้อความ "ลองด้วยคุกกี้แล้วยังโหลดไม่ได้..." · รหัสใหม่ `E_COOKIES_INVALID`, `E_COOKIES_UNAVAILABLE` · network test คลิปจำกัดอายุกับบัญชีสำรอง (AC-CK-09)

## 2. ในโค้ดตอนนี้มีอะไรแล้ว

**มีแล้ว (ใช้ต่อได้):**
- **เซสชันผู้ชมแบบไม่ระบุตัวตน** (`core/visitor_session.py` + `_attach_session` ใน `core/extractor.py`): ไฟล์ `data/visitor-session.txt` ส่งให้ yt-dlp ทาง `cookiefile` ใน probe, โหลดซับ, งานโหลดวิดีโอ/เสียง (`_download_media`) และถ่ายภาพคมตรงจุด (`fetch_frame_piece`) · มีกลไกล็อกและบันทึกไฟล์กลับอย่างปลอดภัยเมื่อหลายงานใช้พร้อมกัน ซึ่งเป็นแม่แบบที่ดีสำหรับไฟล์คุกกี้ของผู้ใช้
- **จุดเดียวที่ต่อ yt-dlp**: ทุกการเรียกผ่าน `YtDlpExtractor._ydl(opts, with_session=...)` จึงสลับ "เซสชันผู้ชม" เป็น "คุกกี้ผู้ใช้" ได้ที่จุดเดียว
- **ค่าตั้ง `cookies`**: มีค่าเริ่มต้น `{enabled:false, source:null, warningAccepted:false}` แล้ว และ `PATCH /settings` ปฏิเสธ key นี้แล้ว (`READ_ONLY` ใน `core/settings.py`) · ฝั่งเว็บมี type ใน `web/src/lib/types.ts`
- **curl_cffi** (ทำตัวเป็นเบราว์เซอร์) ติดตั้งแล้ว (`yt-dlp[curl-cffi]` 2026.8.19, curl-cffi 0.16.3) และมีแถวในหน้าตรวจสุขภาพแล้ว (เขียนไว้ชัดว่าแถวนี้ไม่มีข้อมูลคุกกี้) · สาขา `spike/curl-cffi` เป็นแค่ spike ของซับแปลใน M3 ไม่เกี่ยวกับคุกกี้ผู้ใช้
- **ตัวแปลง error** (`core/yterrors.py`): จับ `E_AGE_RESTRICTED` และ `E_VIDEO_PRIVATE` ได้แล้ว มีไฟล์ตัวอย่างจริงใน `tests/fixtures/errors/`
- **ตัวซ่อนข้อมูลใน log**: มีแต่ `redact_home` (ซ่อน path โฟลเดอร์ผู้ใช้) ใช้ใน log, SSE และ API

**ยังไม่มี:**
- โมดูล `core/cookies.py` (นำเข้า/กรองโดเมน/ลบ/ซ่อนค่า) ที่ BRD วางโครงไว้ · route `/cookies*` · แถวคุกกี้ใน `collect_health` · แท็บ "ขั้นสูง" ในหน้าตั้งค่า (ตอนนี้มีแค่ ทั่วไป · ตรวจสุขภาพ · เกี่ยวกับ) · Checkbox ใน W2 · ตรรกะ "ลองซ้ำด้วยคุกกี้ 1 ครั้ง" · ตัวซ่อนค่าคุกกี้ใน log
- `useCookies` ใน `POST /jobs` ยังได้ 422 ตามที่ตั้งใจ (`docs/m4-followups.md`)
- **ช่องโหว่ที่เจอ:** `yterrors.py` ไม่มีวลีของ **คลิปเฉพาะสมาชิก** ("members-only", "join this channel") และไม่มีไฟล์ตัวอย่าง error แบบนี้ คลิปสมาชิกจึงน่าจะตกไปเป็น `E_UNKNOWN` หรือ `E_VIDEO_UNAVAILABLE` และ**ไม่เข้าเงื่อนไขลองซ้ำด้วยคุกกี้** ทั้งที่เป็น 1 ใน 3 เหตุผลหลักของรอบนี้
- `tests/network_videos.toml` ยังไม่มีคลิปจำกัดอายุสำหรับ AC-CK-09

| F12 | **ข้อมูลประกอบ** | ขีดจำกัดของยูทูป: ผู้ชมทั่วไปราว 300 คลิป/ชม. · บัญชีราว 2000 คลิป/ชม. · แนะนำหน่วง 5-10 วินาทีระหว่างคลิป (คิวเรามีการหน่วงอยู่แล้ว FR-Q-3) · ยูทูปทยอยบังคับ PO Token บางรูปแบบไฟล์อาจหายไปตอนใช้บัญชี | การลองซ้ำด้วยคุกกี้ต้องใช้คุกกี้ทั้งตอนดึงข้อมูล**และ**ตอนโหลดในงานเดียวกัน ไม่งั้นรายการ format ไม่ตรงกัน | https://github.com/yt-dlp/yt-dlp/wiki/Extractors |

อีกเรื่องที่ควรรู้: ตัวเล่นฝังใน W2 (`youtube-nocookie.com`) เล่นคลิปจำกัดอายุไม่ได้อยู่แล้ว ต่อให้เปิดคุกกี้ในแอพ ผู้ใช้จะเห็นข้อความ "เปิดในยูทูป" ตามเดิม ควรบอกพี่พิธไว้ก่อนจะได้ไม่คาดหวังผิด

## 4. เรื่องที่พี่พิธต้องตัดสิน (6 ข้อ)

**1. แหล่งคุกกี้: ใช้ทางไหนบ้าง**
- A. ทั้งสองทางตาม PRD (ไฟล์ cookies.txt + Firefox) โดยเขียนชัดว่า Firefox ต้องล็อกอินด้วย**บัญชีสำรองเท่านั้น**
- B. ไฟล์ cookies.txt อย่างเดียว (Firefox ไว้ทีหลัง)
- C. Firefox อย่างเดียว
- **แนะนำ A** เพราะ Firefox ง่ายกว่าและคุกกี้สดเสมอ (ไม่หมดอายุแบบไฟล์) ส่วนไฟล์เหมาะกับคนที่ไม่อยากลง Firefox · แต่ต้องมีคำเตือนตรงตัวเลือก Firefox ว่าแอพจะใช้บัญชีที่ล็อกอินใน Firefox (F6) · ถ้าพี่อยากลดงาน B ตัดงานได้ราว 2 task

**2. เมื่อยูทูปขอยืนยันว่าไม่ใช่บอท จะใช้คุกกี้ช่วยไหม**
- A. ไม่ใช้ ตาม PRD (พักคิวเหมือนเดิม) แต่แก้เหตุผลในเอกสารเป็น "ปกป้องบัญชี"
- B. ให้ผู้ใช้เลือกเองในแท็บขั้นสูง (Switch แยก ปิดเป็นค่าเริ่มต้น)
- C. ใช้อัตโนมัติเมื่อเปิดคุกกี้ไว้
- **แนะนำ A** ข้อเท็จจริงเปลี่ยนแล้ว (คุกกี้ช่วยได้จริง F2) แต่ตอนโดนตรวจบอท ยูทูปกำลังจับตาคำขอจาก IP นั้นอยู่ การผูกบัญชีเข้าไปตอนนั้นเพิ่มโอกาสบัญชีโดนล็อก ซึ่งเป็นความเสี่ยงที่แพงกว่ารอ 10 นาที

**3. Checkbox "ใช้คุกกี้กับคลิปนี้" ใน W2**
- A. ทำตาม PRD (แสดงในตัวเลือกขั้นสูงเมื่อเปิดคุกกี้ไว้)
- B. ไม่ทำ ให้ระบบลองซ้ำด้วยคุกกี้อัตโนมัติอย่างเดียว
- **แนะนำ B** เพราะทั้ง 3 กรณีของรอบนี้ (จำกัดอายุ ส่วนตัว สมาชิก) ระบบลองซ้ำให้เองอยู่แล้ว Checkbox แทบไม่มีกรณีใช้ แต่เพิ่มปุ่มที่พนักงานต้องเข้าใจ และทำให้บัญชีถูกใช้บ่อยขึ้นโดยไม่จำเป็น · ตัดได้ราว 1-2 task (W2 + `useCookies` ใน API) · ถ้าพี่เคยเจอคลิปที่ต้องล็อกอินถึงจะได้คุณภาพสูง ค่อยเลือก A

**4. Switch "ปิด" กับ "ลบ" ต่างกันอย่างไร**
- A. ตาม PRD: Switch ปิด = หยุดใช้แต่เก็บไฟล์ไว้ (เปิดกลับมาใช้ต่อได้) · "ลบคุกกี้" = ลบไฟล์และปิด
- B. ปิด Switch = ลบไฟล์ทันที (มีอย่างเดียว ไม่มีปุ่มลบแยก)
- **แนะนำ A** สะดวกกับคนที่เปิดใช้เป็นครั้งคราว · แต่ถ้าเครื่องในออฟฟิศใช้ร่วมกันหลายคน (คนละบัญชี Windows ไหม?) B ปลอดภัยกว่า · ตัดสินข้อนี้แล้วทีมจึงออกแบบ API ที่ขาดอยู่ได้ (F10)

**5. สอนผู้ใช้ส่งออก cookies.txt ที่ไหน และละเอียดแค่ไหน**
- A. ใส่คำแนะนำแบบพับได้ในแท็บขั้นสูง 4-5 ขั้น (หน้าต่างส่วนตัว → ล็อกอินบัญชีสำรอง → ส่งออก → ปิดหน้าต่าง) โดยไม่เอ่ยชื่อส่วนขยาย
- B. แบบ A + ระบุชื่อส่วนขยายที่ yt-dlp แนะนำ
- C. ไม่มีในแอพ รอ README ใน M6
- **แนะนำ A** ถ้าไม่บอกเรื่องหน้าต่างส่วนตัว ไฟล์จะหมดอายุเร็วแล้วพนักงานคิดว่าแอพพัง (F3) · ไม่ใส่ชื่อส่วนขยายเพราะส่วนขยายเปลี่ยนเจ้าของหรือกลายเป็นมัลแวร์ได้ ให้ README (M6) ชี้แทนซึ่งแก้ง่ายกว่า

**6. หน้าตรวจสุขภาพจะรู้ได้อย่างไรว่าคุกกี้ "ยังใช้ได้"**
- A. ตาม PRD: บอกแค่สถานะ (ปิด / ใช้ไฟล์ วันที่นำเข้า / ใช้ Firefox / อ่าน Firefox ไม่ได้) ไม่ต่อเน็ต
- B. แบบ A + จำผลการใช้ครั้งล่าสุด เช่น "ใช้ได้ล่าสุด <วันที่>" หรือ "ครั้งล่าสุดใช้ไม่ได้ อาจหมดอายุ" (ข้อเสนอ) โดยไม่ยิงคำขอเพิ่ม
- C. มีปุ่มทดสอบคุกกี้ที่ยิงคำขอจริงไปยูทูป
- **แนะนำ B** คุกกี้หมดอายุเงียบ ๆ ในไม่กี่วันถึงไม่กี่สัปดาห์ B บอกผู้ใช้ได้โดยไม่ใช้บัญชีเพิ่ม ส่วน C ทำให้บัญชีถูกใช้เพิ่มโดยไม่จำเป็น

**เรื่องเล็กที่ทีมเสนอค่าได้เอง (ถามพี่แค่ยืนยัน):** คลิปเฉพาะสมาชิกใช้รหัส `E_VIDEO_PRIVATE` ร่วมกัน (ตรงกับข้อความ PRD อยู่แล้ว) · ถ่ายภาพคมตรงจุดใช้กฎลองซ้ำด้วยคุกกี้เหมือนงานอื่น (F9) · ข้อความ Chrome 127 เพิ่ม Edge (F5) · คำเตือน W7 คงตาม PRD (ข้อความจริงอยู่แล้ว) · ข้อความ error ที่บอก "ตั้งค่า > ขั้นสูง" ยังเป็นข้อความเฉย ๆ ไม่ใช่ลิงก์ ตาม FR-CK-1 (หรือจะให้เป็นลิงก์ ก็ต้องให้พี่อนุมัติเพราะขัด "ไม่มีปุ่มลัด")

## 5. ขนาดงานโดยประมาณ และเรื่องค้างที่รวมเข้ารอบนี้ได้

**ขนาด: ราว 12-15 task** (รอบก่อน ๆ อยู่ที่ 15-17 task) ถ้าเลือกตามคำแนะนำ (ไม่มี Checkbox W2) อยู่ราว 12-13 task แบ่งได้ 3 wave
- backend: `core/cookies.py` (นำเข้า กรองโดเมน เก็บ ลบ) · ตัวซ่อนค่าคุกกี้ใน log + เทส canary (AC-SET-06) · API `/cookies*` + สถานะ · ต่อเข้า `_ydl` (แทนเซสชันผู้ชม อ่าน Firefox) · ตรรกะลองซ้ำ 1 ครั้งใน probe, งานโหลด, ภาพคม, ถ่ายภาพคมตรงจุด · กฎ error สมาชิก + ข้อความรุ่น M5 · แถว `/health` (ราว 6-7 task)
- เว็บ: แท็บ "ขั้นสูง" + route · กล่องเตือน W7 · นำเข้าไฟล์/สถานะ/ลบ · แถวสุขภาพ (ราว 3-4 task)
- เทสรวม e2e + network test คลิปจำกัดอายุ (ต้องมีบัญชีสำรองและคลิปจริง) + เอกสาร (ราว 2-3 task)
- **สิ่งที่ต้องเตรียมนอกโค้ด:** บัญชี Google สำรองสำหรับทดสอบ AC-CK-09 และคลิปจำกัดอายุ/คลิปสมาชิกตัวอย่าง พี่พิธต้องเป็นคนส่งออกคุกกี้เอง (ทีมไม่ใส่รหัสผ่านให้)
