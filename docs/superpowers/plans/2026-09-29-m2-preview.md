# M2 ดูก่อนโหลด (Preview) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task.

**Goal:** A user pastes a YouTube link, lands on the result page (W2), and within 5 seconds sees the clip header plus the fast storyboard frames. From there they can download a contact sheet, a zip of all frames, or a single frame. Multiple links and playlists are listed under the input on W1.

**Scope:** PRD section 10, row M2. APIs: `/resolve`, `/videos/{id}`, `/videos/{id}/storyboard`, `/playlists/{id}` and `/cache/...`. Screens: W1 in full, and the W2 header plus frames. Also contact sheet, zip, and the fake mode for E2E.

**Acceptance criteria:** AC-IN-01..07, AC-PROBE-01..02, AC-FRAME-01, 02, 05, 06, AC-SEC-04 (the `/cache` part) and AC-SEC-05 (the parser part).

**Architecture:**
- **New `core/` modules:** `db`, `inputs`, `yterrors`, `extractor`, `videos`, `storyboard` and `frames`. None of them may import `api/` or `platform/`; they receive what they need through parameters (PRD 6.6).
- **Wiring:** `AppContext` gains the services (db, extractor, fetcher) and `lifecycle.run_app` builds them.
- **Fake mode:** `YT_TOOLKIT_FAKE=1` swaps yt-dlp and HTTP for fixtures under `tests/fixtures/`.
- **Frontend:** adds the `/v/:videoId` route and new shadcn components.

**Tech Stack:** unchanged from M1, plus these shadcn components: dialog, hover-card, context-menu, aspect-ratio, tooltip, button-group. E2E adds `@axe-core/playwright`.

## Owner decisions (2026-09-29, Pete)
1. **Contact sheet and zip download straight through the browser.** New GET endpoints return the file with `Content-Disposition: attachment`. In M4 these move into the queue as the `contact_sheet` / `frames_zip` job kinds and save to the output folder.
2. **Multiple links or a playlist show a result list under the input on W1:**
   - Each clip item has an "open" link to W2.
   - Invalid lines are shown in red with the `E_INVALID_INPUT` message.
   - A playlist item shows its title, clip count, and the note that selecting clips arrives in the next version.
   - The W3 table is M4.
3. **The frame context menu in M2** has two items: "โหลดภาพนี้" (download this frame) and "คัดลอกเวลา" (copy the timecode, format `HH:MM:SS`). "ตั้งจุดเริ่ม/จบ" arrives in M5 and "ดูซับช่วงนี้" in M3.

## Verified facts (probed on 2026-09-29 with yt-dlp 2026.08.19, video `aqz-KE-bpKQ`)
- Probing (`extract_info(download=False)`) takes about 1.7-2.7 s.
- Storyboard formats have `format_note == "storyboard"` and ids `sb0..sb3`. `sb0` is the largest: 320×180, `rows=3`, `columns=3`, `fps≈0.2016` (one frame about every 4.96 s).
- `fragments` is a list of `{url, duration}` with one JPEG grid per fragment. For the 635 s video, sb0 has 15 fragments. Every fragment but the last has `duration≈44.65` (9 frames). The last has `duration≈9.92` (2 frames), for 128 frames in total.
- Frames in a fragment = `round(duration × fps)`, capped at `rows × columns`. Cells past that count are empty and must be skipped (AC-FRAME-02).
- Interval ms = `round(1000 / fps)`. Frame i (global index) has `tMs = i × intervalMs`.
- Fields present: `id, title, channel, duration, upload_date, timestamp, live_status (not_live|is_live|is_upcoming|was_live|post_live), availability, thumbnail, chapters[{start_time,end_time,title}]`.
- Audio formats: `vcodec=="none"`. They carry `language`, `language_preference` and `format_note` (for example "low, DRC").
- Video-only formats: `acodec=="none"`, with `height` and `vcodec` (`avc1…`, `vp09`, `vp9`, `av01`).
- Very short videos (for example the 19 s `jNQXAC9IVRw`) have **no** storyboard formats, which gives `E_NO_STORYBOARD`.
- Big Buck Bunny (`aqz-KE-bpKQ`) is © Blender Foundation under CC BY 3.0. Its metadata and storyboard may be stored as fixtures, with attribution in `tests/fixtures/README.md`.

### Task 1: SQLite database layer

**Files:** `src/yttoolkit/core/db.py`, `src/yttoolkit/config.py` (add `Paths.db`, `Paths.cache`), `tests/unit/test_db.py`

1. `Paths.db` is `data/app.db` and `Paths.cache` is `data/cache`. `Paths.ensure()` creates `data/cache`.
2. `core/db.py`:
   - `SCHEMA_VERSION = 1`. The schema is exactly the SQL in PRD 6.1: `schema_version`, `videos`, `jobs` with index `jobs_status_position`, and `settings`.
   - `class Database(path: Path)` opens `sqlite3` with `check_same_thread=False`, `journal_mode=WAL` and `foreign_keys=ON`. All access goes through an internal `threading.Lock`.
   - Methods:
     - `migrate()`, which is idempotent: create the tables, insert the version, and refuse to open a database newer than the code by raising `RuntimeError`.
     - `execute(sql, params=()) -> list[sqlite3.Row]`
     - `close()`
3. `purge_stale_cache(db, cache_root: Path, now: datetime, days=30) -> int`:
   - Deletes `videos` rows whose `opened_at` is older than `days`, but only those with no `jobs` rows referencing them.
   - Deletes each such video's `cache_root/<video_id>/` folder, ignoring missing folders.
   - Returns the count.
4. Tests:
   - A fresh database migrates. Migrating twice is a no-op.
   - A newer version refuses to open.
   - Concurrent `execute` calls from threads do not raise.
   - Purge removes old rows and their folders, keeps recent rows, and keeps videos that have jobs.

### Task 2: Link parser `core/inputs.py`

**Files:** `src/yttoolkit/core/inputs.py`, `tests/unit/test_inputs.py`

- `@dataclass(frozen=True) class InputItem: input: str; kind: Literal["video","playlist","ambiguous","invalid"]; video_id: str | None = None; playlist_id: str | None = None`
- `parse_line(line: str) -> InputItem` and `parse_text(text: str) -> list[InputItem]`.
- `parse_text` splits on lines, strips whitespace, drops blank lines, and de-duplicates. Two lines are duplicates when they resolve to the same `(kind, video_id, playlist_id)`; the first occurrence wins and keeps order.
- A video ID is `[A-Za-z0-9_-]{11}`. A playlist ID is `[A-Za-z0-9_-]{10,64}`, typically starting `PL`, `UU`, `OL`, `RD` or `LL`.
- Accepted forms:
  - `youtube.com/watch?v=`, including `www.`, `m.` and `music.`
  - `youtu.be/<id>`
  - `youtube.com/shorts/<id>`
  - `youtube.com/live/<id>`
  - `youtube.com/embed/<id>`
  - `youtube-nocookie.com/embed/<id>`
  - a bare 11-character ID
  - links with or without a scheme
  - extra parameters such as `t`, `si`, `feature`, `pp` and `index`
- A link with both `v=` and `list=` is `ambiguous`. If `list` starts with `RD` (a mix), it is treated as `video`, because mixes are endless radio lists.
- `youtube.com/playlist?list=` is `playlist`.
- Anything else is `invalid`, including other domains, a malformed ID, or `javascript:` and other shell-looking strings.
- The parser never executes anything (AC-SEC-05). Test inputs containing `; & | $()` come back as `invalid`.
- Tests:
  - AC-IN-01: `https://youtu.be/dQw4w9WgXcQ?t=42` → video `dQw4w9WgXcQ`.
  - AC-IN-02: every accepted form.
  - AC-IN-03: 5 lines with 1 duplicate and 1 blank → 3 items.
  - AC-IN-04: an invalid line among valid ones.
  - AC-IN-05: `watch?v=…&list=PL…` → ambiguous.
  - Also: the RD mix case, uppercase domains, and a trailing slash.

1. **`yterrors.py`.** `class YtError(Exception): code: str; detail: str`. `classify(message: str) -> str` maps a raw yt-dlp message to a PRD section 7 code:
   - "Sign in to confirm you’re not a bot" / "confirm you're not a bot" → `E_BOT_CHECK`
   - "Private video" → `E_VIDEO_PRIVATE`
   - "Video unavailable" / "This video has been removed" / "This video is no longer available" / "is not a valid URL" / "Incomplete YouTube ID" → `E_VIDEO_UNAVAILABLE`
   - "not made this video available in your country" / "blocked it in your country" → `E_GEO_BLOCKED`
   - "Sign in to confirm your age" / "age-restricted" / "inappropriate for some users" → `E_AGE_RESTRICTED`
   - "This live event will begin" / "Premieres in" / "is_upcoming" → `E_LIVE_NOT_READY`
   - network phrases ("Unable to download", "timed out", "getaddrinfo failed", "Connection reset", "HTTP Error 5") → `E_NETWORK`
   - anything else → `E_UNKNOWN`
   - Matching is case-insensitive.
   - Store at least one realistic message per code as `tests/fixtures/errors/<CODE>-<n>.txt`. Take the texts from yt-dlp's source strings in the installed package (grep `.venv`), and note the source file in the README. A parametrized test runs over every fixture file.
   - Also add `MESSAGES: dict[str, str]`, the Thai message for each code, copied verbatim from PRD section 7. `E_NETWORK` uses `เน็ตหลุด ลองใหม่อีกครั้ง`, because retry counting belongs to the M4 queue. Add that variant to PRD as a note.
2. **`extractor.py`.** An adapter protocol:
   - `probe(video_id) -> dict` (raw info dict)
   - `playlist(playlist_id, limit) -> dict` (flat info: `title` plus `entries[{id,title,duration,thumbnails|thumbnail}]`, reading at most `limit+1` entries so truncation can be detected)
   - `fetch(url) -> bytes` (HTTP GET of image fragments)

   Implementations:
   - `YtDlpExtractor`:
     - Uses `yt_dlp.YoutubeDL({"quiet": True, "no_warnings": True, "skip_download": True, "noplaylist": True})` for probe.
     - For playlist, uses `extract_flat="in_playlist"` and `playlistend=limit+1`.
     - Wraps every `yt_dlp.utils.DownloadError`/`ExtractorError` into `YtError(classify(msg), msg)`.
     - Raises `YtError("E_LIVE_NOT_READY")` when `live_status in {"is_live","is_upcoming"}`, using the PRD message.
     - `fetch` uses `httpx.get(url, timeout=10, follow_redirects=True)`, raising `YtError("E_NETWORK", ...)` on failure.
   - `FakeExtractor(fixtures_root: Path)`:
     - `probe` reads `probe/<id>.json`. A missing id raises `YtError("E_VIDEO_UNAVAILABLE")`, and the special id `PRIVATEVID1` raises `E_VIDEO_PRIVATE`. The live fixture must go through the same live check.
     - `playlist` reads `playlist/<id>.json`.
     - `fetch` maps `https://fake.invalid/storyboard/<name>` to `storyboard/<name>`.
   - Fixture probe JSON files are trimmed real `extract_info` output. Keep only the fields `videos.py` and `storyboard.py` read, and rewrite the storyboard fragment URLs to `https://fake.invalid/storyboard/<id>/M<n>.jpg`.
3. **Fixtures:**
   - `tests/fixtures/probe/aqz-KE-bpKQ.json`: real, with 15 sb0 fragments.
   - `tests/fixtures/storyboard/aqz-KE-bpKQ/M0..M14.jpg`: the real sb0 grids, downloaded once with a throwaway script in the scratchpad (not committed), CC BY 3.0 with attribution.
   - `jNQXAC9IVRw.json`: real, no storyboard.
   - `live_upcoming.json`: synthetic, `live_status: is_upcoming`.
   - `PLfakeplaylist250.json`: synthetic, 250 entries.
   - `tests/fixtures/README.md`: records the sources, the date, the yt-dlp version, and the license and attribution.
4. **Network tests** (marked `network`): probe `aqz-KE-bpKQ` for real; check that storyboard formats exist, that the probe finishes in under 5 s, and that `classify` handles a real private-video message (use a known-private id if one is available, otherwise skip). Run them once at the end of the task and report the result.

### Task 4: Video info service `core/videos.py` (probe + cache)

**Files:** `src/yttoolkit/core/videos.py`, `tests/unit/test_videos.py`

- `to_video_info(raw: dict) -> dict` maps the raw probe to PRD 6.2.1 `VideoInfo`, using camelCase keys:
  - `videoId`, `title`, `channel` (`channel` or `uploader`), `durationS` (int), `publishedAt` (ISO date from `upload_date`/`timestamp`, or omitted), `thumbnailUrl`.
  - `chapters[{startS,endS,title}]`.
  - `video[]`: video-only formats sorted by height desc, then fps desc. Each entry has `formatId`, `height`, `fps`, `vcodec`, `compat` (`vcodec` starts with `avc1`) and `sizeBytes` (`filesize` or `filesize_approx`, or omitted). De-duplicate identical `(height, fps, vcodec family)`, keeping the largest.
  - `audio[]`: audio-only formats. Drop `-drc` variants. Each entry has `formatId`, `language`, `isOriginal`, `acodec` and `abrKbps`.
    - `isOriginal` is true when `format_note` contains "original" or "default" (case-insensitive).
    - If none match, it is true for the formats sharing the highest `language_preference`, when that preference differs among formats.
    - If that is also inconclusive, every entry is false.
  - `hasStoryboard`: whether any `format_note=="storyboard"` exists.
  - `isLive`: whether `live_status == "is_live"`.
- `class VideoService(db, extractor, now=utcnow)`:
  - `get(video_id, refresh=False) -> dict`:
    - If a `videos` row exists with `probed_at` less than 24 h old and `refresh` is false, return the cached `VideoInfo` without calling the extractor (AC-PROBE-01).
    - Otherwise probe, map, and upsert the row (`probe_json` stores the **trimmed raw** subset needed later: `formats` storyboard entries, audio/video formats, chapters and title fields).
    - Update `opened_at` on every `get`.
    - `YtError` propagates.
  - `raw(video_id) -> dict` returns the stored trimmed raw, for the storyboard. It calls `get` first if nothing is cached.
  - `recent(limit, offset=0, q=None) -> (items, total)`, ordered by `opened_at` desc. Items have `videoId`, `title`, `thumbnailUrl`, `durationS`, `outputs: []` (filled from jobs in M4) and `lastAt`. `q` filters on title with LIKE.
  - `playlist(playlist_id, limit=200)` returns `{title,total,truncated,entries[{videoId,title,durationS,thumbnailUrl}]}`. `truncated` is true when the extractor returned more than `limit` entries; only the first `limit` are kept (AC-IN-07). `total` is `playlist_count` if present, else the returned count.
- Tests use `FakeExtractor` with a call counter:
  - Mapping of the fixture, including the compat flags and audio `isOriginal` logic.
  - A cache hit within 24 h makes no extractor call. At 25 h, or with `refresh`, it calls the extractor.
  - The live fixture (probe id `UPCOMINGLV1`) gives `E_LIVE_NOT_READY` (AC-PROBE-02).
  - The playlist is truncated at 200 of 250.
  - `recent` ordering and search.

### Task 5: Storyboard `core/storyboard.py`

**Files:** `src/yttoolkit/core/storyboard.py`, `tests/unit/test_storyboard.py`

- `pick_storyboard(raw) -> dict | None`: among `format_note=="storyboard"` formats, pick the one with the largest `width × height`. Tie-break on the lowest format_id number (`sb0`).
- `plan_frames(sb, duration_s) -> list[FrameSpec(index, fragment, cell, t_ms)]`:
  - `intervalMs = round(1000/fps)`.
  - Per fragment: `n = min(rows*cols, round(fragment.duration * fps))`.
  - Global index `i` gives `t_ms = i * intervalMs`.
  - Drop frames whose `t_ms > duration_s*1000` (AC-FRAME-02).
- `build(video_id, raw, cache_dir: Path, fetch, max_workers=8) -> dict`:
  - If `cache_dir/storyboard/index.json` exists, return it.
  - Otherwise download all fragments in parallel with a `ThreadPoolExecutor` and `fetch`.
  - Crop each cell with Pillow using the storyboard FORMAT's `width`x`height` as the cell size, not image width // cols: the last grid can be partial (e.g. 640x180 holding 2 cells). Grids may be WebP bytes under .jpg names; Pillow detects the real format, and saved crops are real JPEGs. Save as `storyboard/f_<index:04d>.jpg` (quality 90).
  - Write `index.json` = `{intervalMs, frames:[{index,tMs,file}]}` atomically (tmp then replace), and return it.
  - A per-video `threading.Lock` makes concurrent calls build once.
  - No storyboard raises `YtError("E_NO_STORYBOARD")`.
  - A fetch failure removes any partial files and propagates `YtError`.
- Tests:
  - Use synthetic grids generated in the test with Pillow: 3×3 cells, each a distinct solid colour plus its index drawn.
  - Check the cropped cells map to the right colours in the right order.
  - Check that the frame count excludes cells past the duration.
  - Check `tMs` spacing.
  - The cache hit makes no fetch calls.
  - The concurrent build runs once.
  - A missing storyboard gives `E_NO_STORYBOARD`.
  - Also test the real fixture (`aqz-KE-bpKQ`) through `FakeExtractor.fetch`: it must give 128 frames.

2. **Routes** (all under `/api`):

   | Method | Path | Behaviour |
   |---|---|---|
   | POST | `/resolve` | Body `{text}`. Returns `{resolveId, items:[{input, kind, videoId?, playlistId?, error?}]}`. `resolveId` is a uuid4 hex that is not persisted (W3 uses it in M4). Invalid items carry `error:{code:"E_INVALID_INPUT", message}`. |

   | GET | `/videos/{id}/storyboard` | Returns `{intervalMs, frames:[{index,tMs,url}]}`, where `url = /api/cache/<id>/storyboard/f_NNNN.jpg`. |
   | GET | `/videos/{id}/storyboard/contact-sheet.jpg` | Attachment. Filename `<safe title> - contact sheet.jpg`, with RFC 5987 `filename*` for Thai and an ASCII fallback `contact-sheet.jpg`. |
   | GET | `/videos/{id}/storyboard/frames.zip` | Attachment. Filename `<safe title> - frames.zip`. |
   | GET | `/playlists/{id}` | The playlist dict. Id validated. |
   | GET | `/history` | `?q=&limit=&offset=` → `{items, total}`. `limit` defaults to 20, max 100. |
   | GET | `/cache/{videoId}/{path:path}` | Serves files only under `cache_root/<videoId>/`. `videoId` is validated, and the path is checked lexically the same way `static.py`'s `_safe_parts` does (reuse it by moving the helper to a shared module if needed). `..`, backslashes, colons and absolute paths → 404 `E_NOT_FOUND` (AC-SEC-04). `?download=1` adds `Content-Disposition: attachment; filename=frame_HH-MM-SS.jpg`, derived from the frame's tMs in `index.json`. |

   | `E_NETWORK` | 502 |
   | anything else (`E_UNKNOWN`) | 500 |
