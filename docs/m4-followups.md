# งานค้างจาก M4 (ส่งต่อ M5 เป็นต้นไป)

M4 (โหลดและคิว) สร้างครบทั้ง 20 งานย่อยและผ่านการรีวิวรายงานแล้ว (เหลือ gate 3 กับการตรวจสุดท้ายของ controller) เอกสารนี้เก็บเรื่องที่ยังยืนยันกับยูทูปจริงไม่ได้ เรื่องที่พิธตัดสินแล้ว และเรื่องเล็กที่รีวิวเจอแต่ตั้งใจเลื่อนไป รายละเอียดของแต่ละข้ออยู่ใน ledger ของ M4 (`progress.md` ในโฟลเดอร์ `.superpowers/sdd/2026-10-01-m4-downloads/`) ครับ

## ยังไม่ได้ยืนยันกับยูทูปจริง

- **network test ของการโหลด (`tests/network/test_download_network.py`): เขียนเสร็จ ผ่านการ collect แล้ว แต่ยังไม่ได้รันจริง** เพราะโหลดไฟล์วิดีโอจริงรวมประมาณ 100-200 MB ต้องรอพิธอนุมัติก่อน (กฎ: ดาวน์โหลดไฟล์ต้องขออนุญาตก่อน) รันเองด้วย `uv run pytest -m network -q tests/network/test_download_network.py -s` แล้วจดผลที่นี่
  - ตรวจ AC-VID-01, 02, 03, 04, 05 (แบบกลับด้าน), 08, 09 และ AC-AUD-01..04 ด้วย ffprobe กับไฟล์ที่ handler ของคิวสร้างจริง
  - ตรวจเพิ่มตามรายการของรีวิว T9: compat (avc1 + mp4a), `maxQuality` (`bv*`+เสียงดีที่สุด) ทั้งแบบเลือก format และอัตโนมัติ, เสียงล้วน (format 140) และ `noAudio` แต่ละแบบต้องได้ไฟล์ mp4/m4a ที่ถูกต้อง · คลิปแนวตั้งต้องได้ 1080 ที่ด้านสั้น · ยกเลิกกลางการโหลดหยุดภายใน 3 วินาทีและไม่มีไฟล์ค้าง · ไฟล์เซสชันผู้ชม (`data/visitor-session.txt`) ไม่เปลี่ยนคนหลังโหลด
  - คลิปที่ใช้อยู่ในหัวข้อ `[downloads]` ของ `tests/network_videos.toml` (probe ข้อมูลอย่างเดียวเมื่อ 2026-10-02 ยืนยันความสูง ภาษาเสียง และสัญญาอนุญาตแล้ว ยังไม่ได้โหลด)
- **เรื่องที่ network test ยังไม่ครอบคลุม** (ต้องใช้คลิปที่หาแบบกำหนดไม่ได้ จึงตรวจด้วยข้อมูลปลอมและรอเจอของจริงตอนใช้งาน):
  - 403 จริงที่ดึงข้อมูลใหม่รอบเดียวแล้วหาย (Q2) และ 403 ที่ไม่หาย → `E_YT_REFUSED`
  - 429 จริงที่กลายเป็น `E_BOT_CHECK` แล้วพักคิว (ตรวจมือแถว `M4-BATCH` ถ้าเจอ)
  - คลิปที่เพิ่งจบไลฟ์ (post-live) และคลิปอายุไม่ถึง 2 วันที่มีแต่ HLS (ไม่มีไฟล์แบบแบ่งก้อน HTTP) รวมถึงการยกเลิกบน HLS ว่าหยุดภายใน 3 วินาทีไหม (ที่ตรวจแล้วคือ HTTP แบบแบ่งก้อน)
- **AC-VID-05 ตรวจแบบกลับด้าน:** ยังหาคลิปภาษาอังกฤษที่ยูทูปพากย์ไทยและสั้นพอสำหรับ network test ไม่เจอ จึงใช้ `8lpOfyoxcvU` (เสียงไทยต้นฉบับ + พากย์ en-US) เลือก `en` แล้วตรวจว่าแทร็กในไฟล์เป็น `eng` ไม่ใช่ original กฎเลือกภาษาเป็นโค้ดเดียวกันทุกภาษา แต่ยังไม่เคยเห็นกรณี "ไทย" กับคลิปจริง · ถ้าเจอคลิปแบบนั้น (พิธหรือพี่เบิร์ดอาจรู้จัก) ให้ใส่ id ใน `[downloads]` แล้วเพิ่มเทสเลือก `th` · ตรวจมือที่แถว `M4-DUB`
- **คลิป 4K ที่สั้นพอมีแล้ว (`kwmHaXUAa0M` 10 วินาที) AC-VID-02 จึงยังเป็นเทสอัตโนมัติ** ไม่ต้องย้ายเป็นแถวตรวจมือ ตรวจมือเหลือแค่ว่าไฟล์ 4K เปิดได้ในโปรแกรมตัดต่อของทีม (แถว `M4-4K`)
- **ความคืบหน้าของการโหลดจริงรีเซ็ตทุกแทร็ก** (ภาพ 0→1 แล้วเสียง 0→1) แถบคิวรีเซ็ตตามขั้นตอนอยู่แล้ว ข้อมูลปลอมไม่เห็นพฤติกรรมนี้ ให้ดูตอนตรวจมือว่าแถบไม่ดูแปลก
- **ซับแปลอัตโนมัติ (M3-TLANG):** ยังค้างเหมือนใน `docs/m3-followups.md` (รันซ้ำบนเน็ตออฟฟิศ)
- **ฝังซับกับซับของยูทูปจริง:** ข้อความที่ฝังเทียบกับ `.srt` ของ preset เดียวกันใน network test ครอบคลุมเฉพาะ `th-orig` ของ `88o5Sk8_m1Y` · ซับของเจ้าของคลิปที่ไม่มีเวลาระดับคำ ยังไม่ได้ตรวจการฝังกับคลิปจริงใน network test

## พิธตัดสินแล้ว (M4)

- **Q1-Q8 เลือกตามที่แนะนำทั้งหมด (2026-10-01)** ดู BRD ข้อ 19 #84-#91
- **"ไม่เอาเสียง" ไม่ถูกจำข้ามคลิป** (BRD #100) · **ตัวเลือกอัตโนมัติเมื่อเปิด "ความละเอียดสูงสุด" ชื่อ "สูงสุดที่คลิปนี้มี"** (#101) · **ป้ายของโหมด "เปิดได้ทุกที่" แสดงเพดานที่ใช้อยู่จริง** "เปิดได้ทุกที่ สูงสุด {h}p (แนะนำ)" (#102)
- **เป้าหมายจอแคบคือหน้าต่างแคบหรือซูม 200% ไม่ใช่มือถือ** (BRD #83) M4 ไม่เพิ่มงานเกลาเพื่อมือถือ เมนูบนหัวต่ำกว่า 640 px เป็นไอคอน (#105)
- **"ตั้งจุดเริ่ม/ตั้งจุดจบ" จากตัวเล่นคลิปเป็นของ M5** (BRD #81) พร้อม AC-VID-10 ส่วนที่ 1 (ฝังซับตามช่วงเวลา, #106)

## เลื่อนไป M5

- **ตัวเลือกขั้นสูงของ W2** (ซ่อนอยู่ตอนนี้): ช่วงเวลา แยกตาม chapter ตัดโฆษณา คุกกี้ · API ปฏิเสธ `range` `sponsorblock` `useCookies` `splitChapters: true` และ `frames_sharp` ด้วย 422 จนกว่า M5 จะเปิด
- **ภาพเฟรมโหมดคม** (`frames_sharp`) และ `source: "sharp"` ของ contact sheet / zip
- **คุกกี้ผู้ใช้:** ตอน FR-CK-7 ให้ใช้คุกกี้ต้องใช้แทนเซสชันผู้ชมของการโหลด (ไม่ใช้สองไฟล์พร้อมกัน) เหมือนที่จดไว้ใน M3

## เลื่อนไป M6

- **รูปแบบชื่อไฟล์ (`filenameStyle`)**: M4 ใช้แบบ "ชื่อคลิป" แบบเดียว (ตัวตั้งค่ารับค่าไว้แล้วแต่ยังไม่มีผลกับชื่อไฟล์)
- **ล้างข้อมูลชั่วคราว สำรอง/นำเข้าค่าตั้ง สถิติ** และ `lastUsed` ฝั่งเซิร์ฟเวอร์ (W2 จำค่าในเบราว์เซอร์ไปก่อน BRD #92)
- **ทำให้โค้ดหน้าเว็บเป็นก้อนเดียวกัน:** ฟังก์ชันบอกความเร็ว `formatSpeed` ของแถบคิว (`web/src/components/queue/job-text.ts`) กับ `formatBytes` ของ `web/src/lib/format.ts` ทำเรื่องคล้ายกัน (ปัดเศษต่างกันเล็กน้อย) ควรรวมกันตอนเก็บงาน

## เรื่องเล็กที่รับไว้ก่อน (ไม่กระทบการใช้งานปกติ)

- **ยกเลิกงาน:** ขั้นสั้น ๆ (ดึงข้อมูลคลิป สร้างซับสำหรับฝัง ใส่ปก ประกอบภาพเฟรมของ contact sheet และ zip) ไม่ตรวจการยกเลิกระหว่างขั้น แต่ตรวจก่อนเริ่มขั้นถัดไป จึงหยุดช้ากว่า 3 วินาทีได้เมื่อขั้นนั้นช้า (เช่น คลิปยาวมากหรือเน็ตช้า) · การยกเลิกที่มาถึงหลังไฟล์เข้าที่แล้วนับว่างานเสร็จ
- **ปิดโปรแกรม:** กรณีแย่สุด (หยุดคิวรอ 5 วินาที + รอการเชื่อมต่อเดิม 3 วินาที) เกินเวลาที่ `stop.bat` รอก่อนบังคับปิด (10 วินาที) ได้ เกิดเฉพาะเมื่อมีงานที่ไม่ตอบรับการยกเลิก (เช่น ย้ายไฟล์ข้ามไดรฟ์ขนาดใหญ่) ซึ่งจะถูกบังคับปิดและกลายเป็น "หยุดกลางคัน" ตามปกติ · ช่วงที่ปิดอยู่ (ไม่เกิน 5 วินาที) เซิร์ฟเวอร์ยังรับงานใหม่ได้ งานนั้นค้างเป็น "รอ" แล้วเริ่มตอนเปิดครั้งหน้า
- **กู้งานตอนเปิด:** ระบบลบไฟล์ 0 ไบต์และ `.part` ในโฟลเดอร์ผลลัพธ์ที่ตั้งไว้ ณ ตอนเปิด ถ้าผู้ใช้เปลี่ยนโฟลเดอร์ผลลัพธ์หลังงานหยุดกลางคัน ไฟล์ค้างในโฟลเดอร์เก่าจะไม่ถูกลบ (ปลอดภัยไว้ก่อน ไม่แตะโฟลเดอร์ที่ไม่ได้ตั้งไว้) · ต้องเพิ่มชนิดไฟล์ใน `_SWEEP_*` ของ `lifecycle.py` เมื่อมีชนิดไฟล์ผลลัพธ์ใหม่ (เช่น M5)
- **log และ tray (รีวิว T18 ข้อ M3b, M8):** ตัวกรองที่เปลี่ยน path โฟลเดอร์ผู้ใช้เป็น `~` ติดตั้งตอนตั้งค่า log ของแอพ จึงยังไม่ทำงานกับความล้มเหลวที่เกิดก่อนตั้งค่า log ใน `__main__` และในคำสั่ง probe · บน macOS การอัปเดตเมนู tray ต้องส่งไปทำที่ main thread (ตัวรีเฟรชเมนูตอนนี้ทำใน thread แยก) ตรวจตอน M7
- **กู้งานตอนเปิด (รีวิว T18 ข้อ M2):** ตัวล้างไฟล์ค้างโหลดงาน `done` ทุกงานเข้ามาตรวจทุกครั้งที่เปิดโปรแกรม ควรเพิ่มคำค้นใน `JobStore` ตาม `video_id` (หรือคลิป) แทน เพื่อไม่ให้ช้าลงเมื่อประวัติงานเยอะ
- **หน้าประวัติ (W5):** หลังกด "แสดงเพิ่ม" โฟกัสไปที่แถวแรกที่เพิ่มเข้ามา แต่ยังไม่ล้างตัวจำแถวที่รับโฟกัสเมื่อดึงหน้าต่อไปเสร็จ และยังไม่ใส่ `preventScroll` ตอนย้ายโฟกัส (เรื่องเล็กจากรีวิว T13) · ลากเลือกข้อความในชื่อคลิปไม่ได้ เพราะทั้งแถวเป็นลิงก์ (เหมือน "ล่าสุด" ของหน้าแรก)
- **หน้า W2 กับค่าตั้ง:** (1) กดโหลดก่อนที่ค่าตั้งโหลดเสร็จ ใช้เพดาน 1080 (2) คุณภาพที่จำไว้เป็นความสูงเกินเพดานใหม่ (เช่น 1080 หลังเปลี่ยนเป็น 720) กลายเป็น "อัตโนมัติ" เงียบ ๆ (3) เทส e2e ตรวจเฉพาะข้อความตัวเลือกอัตโนมัติ ไม่ตรวจค่า `maxHeight` ที่ส่งในทุกกรณี
- **หน้าเลือกคลิป (W3):** (1) ตัวนับจำนวนคลิปอาจนับแถวที่ไม่มี `videoId` (ทางทฤษฎีเท่านั้น) (2) ถ้าหน้าแรกเจอ bot check แล้ว การเปิดเพลย์ลิสต์ใน W3 ขึ้นข้อความทั่วไปพร้อมปุ่มลองใหม่ที่ล้มซ้ำจนกว่าจะวิเคราะห์ลิงก์ใหม่ที่หน้าแรก
- **คิวงาน (W4):** ข้อความตอนโหลดรายการคิวไม่สำเร็จใช้ข้อความทั่วไป "ทำรายการนี้ไม่สำเร็จ ลองรีเฟรชหน้าเว็บ" (ยังไม่มีข้อความเฉพาะ)
- **หน้าแรก (W1) กับ bot check:** ถ้าข้อมูลคลิปมาจาก cache เก่า (stale) แทนการเรียกยูทูป จะไม่เห็นว่าโดน bot check และคิวไม่ถูกพัก (รีวิว T12)
- **เทส e2e ที่ล้มเฉพาะตอนรันทั้งชุด (flaky):** `web/e2e/video-tabs.spec.ts:176` "ปุ่มคลิปถัดไปอยู่ที่แท็บเดิม…" ล้มเมื่อรันทั้งชุดตอนเครื่องมีโหลดแต่ผ่าน 4 จาก 4 ครั้งเมื่อรันเดี่ยว ต้องตรวจว่าลิงก์ "ถัดไป" อาจถือแท็บเก่าค้างทันทีหลังเปลี่ยนแท็บหรือไม่ (ถ้าใช่คือบั๊กจริงของหน้าเว็บ ไม่ใช่เทสเอง)
- **เทส integration ที่ล้มเฉพาะตอนเครื่องมีโหลด (flaky):** `tests/integration/test_queue_serve.py::test_job_running_when_app_dies_is_interrupted_after_restart_and_can_retry` ล้มด้วย "serve ไม่ขึ้นใน 30 วินาที" ตอนรันทั้งชุด `pytest` พร้อมกับงานอื่นบนเครื่อง ผ่านเมื่อรันไฟล์เดียว (พบ 1 ครั้งตอนรันทั้งชุดเมื่อ 2026-10-02) · ควรเพิ่มเวลารอเริ่มของ serve ในเทสกลุ่มนี้หรือลดจำนวนที่รันพร้อมกัน
- **log รก:** backend ของ e2e project `queue` เขียนบรรทัด `ConnectionResetError: [WinError 10054]` จำนวนมากเมื่อเบราว์เซอร์ที่เปิด SSE ตัดการเชื่อมต่อ (เสียงรบกวนของ asyncio บน Windows) ไม่กระทบการทำงาน ควรกรองให้เงียบ
- **เรื่องเล็กจากรีวิวของงานย่อย T1, T2, T3, T6** ที่ข้ามตามที่ controller สั่ง (ข้อ 4 ของ T1, ข้อ 9-10 ของ T2, ข้อ 6, 7, 9 ของ T3, ข้อ 2 ของ T6) ไม่กระทบการใช้งาน รายละเอียดอยู่ใน ledger
- **เทส e2e ของคิว:** `queue-*.spec.ts` ใช้ backend ตัวเดียวกัน spec ที่เขียนใหม่ห้ามนับยอดรวมของแถบคิว (รวมงานของ spec อื่น) ให้ตรวจเฉพาะงานของคลิปตัวเอง
