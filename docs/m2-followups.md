# งานค้างจาก M2 (ส่งต่อ M3/M4)

M2 (ดูภาพเฟรม) ผ่านรีวิวและพิธทดลองใช้จริง 2 รอบแล้ว แล้วรวมเข้า main วันที่ 2026-09-30 ครับ เอกสารนี้เก็บเรื่องเล็กที่รีวิวเจอแต่ตั้งใจเลื่อนไป พร้อมโน้ตที่ต้องใช้ตอนวางแผนรอบถัดไป

## ทำแล้วใน M3

- **หน้าคลิป (W2) แยกเป็นแท็บ:** ทำแล้วใน M3 (แท็บภาพเฟรม · ซับ · ทรานสคริปต์ ตาม PRD W2 และ BRD การตัดสินใจ #48) ส่วนแท็บวิดีโอและเสียงมาใน M4

## ทำแล้วใน M4

- **Retry: ทำแล้ว** 4xx ที่ไม่ใช่ 429 ไม่เป็น `E_NETWORK` แล้ว ได้รหัสใหม่ `E_YT_REFUSED` (PRD ข้อ 7, BRD #85) ตัวโหลดดึงข้อมูลใหม่แล้วโหลดซ้ำหนึ่งครั้ง ไม่ได้ก็ล้ม ไม่ลองซ้ำ ไม่เบรกฉุกเฉิน · ผลข้างเคียงที่ตั้งใจ: probe และคอมเมนต์ปักหมุดที่ได้ 4xx ก็เป็น `E_YT_REFUSED` · probe ที่ cache หมดอายุแต่มีแถวเดิมในเครื่องยังใช้ข้อมูลเดิมไปก่อน (`E_YT_REFUSED` อยู่ใน `STALE_OK_CODES` ของ `core/videos.py`) ส่วนไม่มีแถวเดิมหรือขอ `?refresh=1` ได้ 502 · คอมเมนต์ปักหมุดไม่ลองทางสำรอง
- **เมนูบนมือถือ ("ประวัติ" ใส่ไม่ลง): ทำแล้ว** ต่ำกว่า 640 px เมนูบนหัวเหลือแค่ไอคอน มี `aria-label` และ Tooltip (BRD #105) เมนู "ประวัติ" อยู่ระหว่าง "หน้าแรก" กับ "ตั้งค่า"

## เรื่องเล็กที่รับไว้ก่อน (ไม่กระทบการใช้งานปกติ)

- **Storyboard:** ถ้ามีแถวเดียวและ fragment เดียว จะใช้ความกว้างที่ yt-dlp รายงาน ไม่ได้วัดจากภาพจริง
- **ตอนปิดแอพ:** การดึงภาพผ่าน httpx อาจแข่งกับการปิด client
- **หน้าแรก (W1):**
  - ถ้าใช้ข้อมูลเก่าสำรองอยู่ จะไม่เห็นว่าโดน bot check
  - การลองเชื่อมต่อใหม่ตอนออฟไลน์ทำทีละคลิป
- **หน้าคลิป (W2):**
  - เจอ `E_BOT_CHECK` ตอนดูภาพเฟรมแล้วไม่มีปุ่มกลับหน้าแรก
  - โฟกัสอาจเด้งกลับไปที่กล่อง error ถ้าผู้ใช้กดลองใหม่แล้วพลาดซ้ำ
- **Toast:** ข้อความซ้ำเมื่อดึงข้อมูลใหม่ไม่สำเร็จหลายครั้ง
- **เมนูคลิกขวา:** ปุ่มที่ปิดใช้งานยังมีสีพื้นตอนชี้เมาส์ และยังมีกรณีขอบของ `keyboardOpenRef`
- **ตัวดึงลิงก์:**
  - คำที่ผสมตัวพิมพ์เล็กและใหญ่ยาว 11 ตัวอักษร (เช่น `JavaScript1`) ยังถูกนับเป็นรหัสคลิปเมื่อวางคู่กับลิงก์
  - ลิงก์ `_youtu.be/ID`: ตัวจับตอนกด Ctrl+V ถือว่าเป็นลิงก์ยูทูป แต่ฝั่งเซิร์ฟเวอร์ไม่รับ
