# งานค้างจาก M1: ปิดแล้ว

รายการงานค้างที่ได้จากรีวิว M1 ปิดครบในงานชุด "M1 follow-ups" แล้วครับ เอกสารนี้เก็บไว้เป็นบันทึกว่าปิดอะไรไปบ้าง และอะไรที่ตั้งใจเว้นไว้

## ปิดแล้ว

- **วงจรเปิดและปิดแอพ:**
  - เริ่มแอพแล้วล้าง `app.json` เก่าทิ้ง
  - `start` รับช่วงต่อเมื่อ lock ว่าง
  - `stop` ฆ่าโปรเซสเฉพาะเมื่อ `app.json` ยังชี้ pid และ `started_at` เดิม
  - เก็บกวาดเมื่อเริ่มแอพไม่ทันเวลา
  - เปิดไฟล์ lock ไม่ได้ จะบันทึกลง log ครั้งเดียว
  - `app.log` หมุนไฟล์
  - คำสั่งใหม่ `yttoolkit wait`
  - `find_running` ตรวจ pid จาก ping
- **start.bat และ stop.bat:**
  - `start.bat` รอจนแอพเปิด ถ้าไม่ขึ้นจะแสดงหน้าจอแจ้งพร้อมที่อยู่ไฟล์ log
  - ข้าม `uv sync` ตอนแอพเปิดอยู่
  - คืนค่า code page ของคอนโซล
  - ตั้ง `PYTHONUTF8`
  - เพิ่มหมายเหตุสำหรับนักพัฒนาใน README
  - เพิ่มแถว AC-LIFE-02b ใน `docs/acceptance.md`
- **ส่วนที่ขึ้นกับระบบปฏิบัติการ:**
  - `yttoolkit/platform/` มี `popen_flags`, `exe_name` และ `ffmpeg_auto_install`
  - ไม่มีการเช็ก OS นอกโฟลเดอร์ `platform/` อีก
  - Windows ctypes กำหนด argtypes และโหลดแบบ lazy
  - เพิ่มเทสของ platform
  - จัดสถานะดิสก์และ JS runtime ให้เรียบร้อย
- **API และเครื่องมือ:**
  - error ทุกแบบ (404, 422, อื่นๆ, 500) อยู่ในรูป `{"error":{...}}` เหมือนกัน
  - ตัดโฟลเดอร์ home ออกจาก `detail`
  - ตรวจ websocket ใน `LocalOnlyMiddleware`
  - ปฏิเสธ header ความปลอดภัยที่ซ้ำ
  - แก้ทางเข้า `index.html` ทางลัด
  - จัดการกรณีขอบของการติดตั้ง ffmpeg
  - เพิ่ม workflow อัปเดต yt-dlp ทุกวัน ซึ่งสั่งรัน CI เต็มชุดต่อให้ด้วย
  - ตัวตรวจสุขภาพ yt-dlp เทียบกับรุ่นใหม่สุดบน PyPI จึงไม่เตือนผิด
- **หน้าเว็บ:**
  - `api()` ใส่ `Content-Type` ให้ถูกต้อง
  - เพิ่ม unit test
  - แยก `use-health.ts` ออกมาเป็นไฟล์ของตัวเอง
  - toast ตอนติดตั้ง ffmpeg และตอนปิดโปรแกรม พร้อม spinner
  - ลิงก์ "ตั้งค่า" เป็น `<a>` จริง
  - ไม่มีจอขาวแวบตอนใช้ธีมมืด
  - spinner ใช้ป้ายภาษาไทย
  - แก้หน้าแรก
  - e2e ตรวจเวอร์ชันด้วย regex และรีเซ็ต data root
  - เพิ่ม `web/README`
- **CI:**
  - job `web` ตรึงที่ `ubuntu-24.04` เพื่อให้ขั้นตรวจ `web/dist` ไม่พังเมื่อ `ubuntu-latest` ย้ายไป Ubuntu 26
  - job `e2e` cache browser ของ Playwright โดยใช้ `web/package-lock.json` เป็น key

## ตั้งใจเว้นไว้

- **ตรวจด้วยมือตาม `docs/acceptance.md` ส่วน M1:** บัญชี Windows ใหม่, ปิดแอพ 3 ทาง, ถอดสายเน็ต, เปิดจากเครื่องอื่นในวง LAN และหน้าจอแจ้งเมื่อเปิดไม่สำเร็จ ข้อนี้ต้องให้คนลองบนเครื่องจริง สคริปต์ทำแทนไม่ได้ครับ
- **FR-SET-3 ปุ่ม "ตรวจหาอัปเดต":** ยังไม่มีระบบอัปเดตตัวแอพ ตามแผนจะทำใน M4 หรือ M6
- **FR-SET-5 และ AC-SET-03 ถึง AC-SET-05 (รายงานวินิจฉัย และปุ่ม "คัดลอกข้อมูลแจ้งปัญหา"):** ตามแผนอยู่ใน M6 ครับ
- **ไฟล์ `.command` สำหรับเปิดและปิดบน macOS และ ffmpeg บน macOS:** ตามแผนอยู่ใน M7 ครับ
- **Branch protection ของ `main`:** workflow อัปเดต yt-dlp push ตรงเข้า `main` ถ้าวันไหนเปิด branch protection จะ push ไม่ผ่าน ต้องกลับมาทบทวนตอนนั้น ตอนนี้ยังไม่ได้เปิดครับ
