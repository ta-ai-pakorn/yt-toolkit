# งานค้างจาก M3 (ส่งต่อ M4 เป็นต้นไป)

M3 (ซับและทรานสคริปต์) ผ่านรีวิวทั้ง branch แล้ว และแก้เรื่องที่รีวิวรอบสุดท้ายเจอเสร็จเมื่อ 2026-10-01 พิธลองใช้จริงแล้วและแก้ตามที่พิธบอกรอบแรกเสร็จ (ดูหัวข้อ "พิธตัดสินแล้ว") ครับ รอรวมเข้า main เอกสารนี้เก็บเรื่องที่ยังยืนยันไม่ได้ เรื่องที่รอตัดสิน และเรื่องเล็กที่รีวิวเจอแต่ตั้งใจเลื่อนไป

  - แอพตอนนี้ขึ้นข้อความ "ยูทูปยังไม่ให้โหลดซับแปลอัตโนมัติในตอนนี้ เลือกซับภาษาต้นฉบับแทน" (`E_TRANSLATION_BLOCKED`) พร้อมปุ่ม "ใช้ซับภาษาต้นฉบับ" ไม่ใช่ข้อความเรื่องบอทแบบเดิม

- **spike `curl_cffi` (ยังค้าง รอพิธตัดสิน):** ลองใน branch `spike/curl-cffi` (0573d7a มีแค่ `pyproject.toml` / `uv.lock`) เมื่อ 2026-10-01 ครับ

  - ข้อเสนอ: เก็บ jar ที่ `data/visitor-session.txt` ใช้ร่วมกันระหว่าง probe กับการโหลดซับ + หน้าเว็บนับถอยหลัง "ซับแปลพร้อมในอีก ~N วินาที" แล้วลองเองหนึ่งครั้ง + คง `E_TRANSLATION_BLOCKED` ไว้เป็นทางถอย · `curl_cffi` ใส่เป็นประกันเพิ่มได้ (`yt-dlp[default,curl-cffi]`)

## ทำแล้วในรอบแก้สุดท้ายของ M3

- ซับแปลที่โดน 429 ได้รหัสใหม่ `E_TRANSLATION_BLOCKED` (HTTP 503) แทน `E_BOT_CHECK` ซับของเจ้าของคลิปและซับภาษาต้นฉบับยังเป็น `E_BOT_CHECK` เหมือนเดิม
- error ที่ลองใหม่ไม่ช่วยของแทร็กไม่มีปุ่มลองใหม่ และไม่ยิงคำขอซ้ำเมื่อสลับแท็บ · ปุ่มโหลดไฟล์และคัดลอกกดไม่ได้หลัง error ทุกแบบ
- `track=` ใน URL ที่คลิปไม่มี (ลิงก์เก่า พิมพ์ผิด) ใช้แทร็กเริ่มต้นของคลิปแทน
- แทร็กที่อ่านแล้วไม่มีข้อความ ทรานสคริปต์ขึ้น "คลิปนี้ไม่มีซับ" เหมือนแท็บซับ
- แท็บซับและทรานสคริปต์ใช้ค่าความยาวซับก้อนเดียวกัน แม้เบราว์เซอร์บล็อก storage ก็ไม่ถอยกลับเป็น "กลาง" (Q4)
- หัวข้อแท็บทรานสคริปต์ใช้ id จาก `useId` แทน id ตายตัว

## เลื่อนไป M4

- **คิวงาน:** `E_TRANSLATION_BLOCKED` ต้องไม่พักคิว (ต่างจาก `E_BOT_CHECK` ที่ M4 จะพักทั้งคิว 10 นาที) เป็นแค่งานนั้นล้มเหลว
- **ลิงก์หมดอายุ:** json3 ที่พลาดด้วย `E_NETWORK` จะ probe ใหม่แล้วลอง json3 อีกรอบเดียว ไม่ลอง vtt ต่อ ถ้าย้ายการโหลดซับเข้าคิวแล้วค่อยทบทวนพร้อมกฎลองใหม่ 3 ครั้ง

## เลื่อนไป M6 (การเข้าถึง)

- **วงโฟกัส:** `ring-ring/50` ทั้งแอพมีคอนทราสต์กับพื้นราว 1.5:1 และวงโฟกัสของ M2 ในธีมสว่างราว 1.63:1 ต่ำกว่าเกณฑ์ 3:1 ของขอบที่ไม่ใช่ตัวอักษร

## เรื่องเล็กที่รับไว้ก่อน (ไม่กระทบการใช้งานปกติ)

- **PyThaiNLP:**
  - ถ้าผู้ใช้ตั้ง `PYTHAINLP_DATA` เป็นค่าว่าง ยังไม่ได้จัดการแยก
  - อักขระ U+200B (zero-width space) ยังถูกนับเป็นคำของตัวเอง
- **รายการแทร็ก (`core/tracks.py`):**
  - ตัวเช็กแทร็กซ้ำกับ `<ภาษา>-orig` ยังไม่ครอบกรณีที่ `-orig` มีแต่ลิงก์ซับแปล (แก้บรรทัดเดียว)
  - fixture `NOORIGSUB01` ใช้ชื่อแทร็กเหมือนรหัสภาษา
- **บริการซับ (`core/subtitles.py`):**
  - ตรวจ track id ซ้ำหลายชั้น
  - ตัวล็อกต่อแทร็กเก็บไว้ไม่มีวันลบ (ใช้หน่วยความจำนิดเดียวต่อแทร็กที่เคยเปิด)
  - เก็บไฟล์ซับดิบไว้ใน cache ข้าง token แต่ยังไม่มีอะไรใช้ (เก็บไว้เผื่อ parser รุ่นใหม่ไม่ต้องโหลดซ้ำ)
  - `tokensPerCue` ที่ส่งมาต้องอยู่ในช่วง 1-20 แม้โหมดนับตัวอักษร (เข้มกว่าสัญญา C5 เขียนไว้ใน PRD แล้ว หน้าเว็บไม่ส่งค่านี้ในโหมดนั้น)
- **เทส:**
  - เทส export โหมดนับเป็นคำยังตรวจแค่ผ่าน ไม่ได้ตรวจเนื้อไฟล์ละเอียด
  - fixture ที่ตั้งค่าตัวแปรสภาพแวดล้อมของเทสมีโค้ดซ้ำกันอยู่
  - `FakeExtractor` โยน exception ดิบเมื่อ json3 ปลอมเสีย (กระทบแค่ตัวปลอม)
- **หน้าเว็บ:** ลูกศร ▼ ที่ซ่อนไว้ในช่องเลือกแทร็กติดมากับ textContent (เทส e2e อ่านเฉพาะส่วนค่าแทน)
